## 1. PLC Instructions

课件四块：数制 → 算术与 MOV → 转换与比较 → 程序控制。

### 1.1 数制（Number system）

PLC 和所有计算机一样，内部只认 **0 和 1**。人眼看长串 0/1 很痛苦，所以会出现二进制、八进制、十六进制、BCD。

#### 1.1.1 二进制 ↔ 十进制

**二进制 → 十进制**：每一位的权是 \(2^k\)。该位为 1 就加上对应权，为 0 就加 0。

例：\(1011_2 = 1\cdot 2^3 + 0\cdot 2^2 + 1\cdot 2^1 + 1\cdot 2^0 = 8+0+2+1 = 11_{10}\)

课堂例子：位置 2 上的 1，权是 \(2^2=4\)。

**十进制 → 二进制**：反复除以 2，记下余数，**从下往上**读。

课堂例子：把 **123** 写成二进制。

```
123 ÷ 2 = 61  余 1
 61 ÷ 2 = 30  余 1
 30 ÷ 2 = 15  余 0
 15 ÷ 2 =  7  余 1
  7 ÷ 2 =  3  余 1
  3 ÷ 2 =  1  余 1
  1 ÷ 2 =  0  余 1
```

余数从下往上：\(1111011_2\)。验算：\(64+32+16+8+0+2+1=123\)。

#### 1.1.2 字节、字（先纠正一个口误）

| 名称 | 位数 | 说明 |
|------|------|------|
| bit | 1 | 一个 0 或 1 |
| byte | 8 | 常见最小成组单位 |
| word | 16 | PLC 里模拟量、整数通常占 **一个 word** |

老师讲数制时随口把 8 位叫成 word，后面讲 Siemens 时改回正确说法：**W = word = 16 bit**。记后面这个。

#### 1.1.3 有符号数：为什么必须用 2 的补码

只有 0 和 1，无法写负号。三种办法：

**方法 A：符号位（sign-magnitude）**  
最高位 0=正、1=负，其余位表示绝对值。

4 位例子：

- \(+3 = 0011\)
- \(-3 = 1011\)（左边 1 表示负）

问题：\(0011 + 1011 = 1110\)，按符号位读成 \(-6\)，但 \(3+(-3)\) 应该是 0。加法直接坏掉。

**方法 B：1 的补码（ones' complement）**  
按位取反（0↔1）。

**方法 C：2 的补码（two's complement）——计算机真正用的**

步骤（对 **N 位** 整数）：

1. 先写该数绝对值的 N 位二进制（左边补 0）
2. **全部按位取反**（得到 1 的补码）
3. **再加 1**（得到 2 的补码）

正数不变。2 的补码的代数意义：相当于 \(2^N - |x|\)。

4 位下 \(+3=0011\)，\(-3\)：

```
0011  取反 → 1100   再 +1 → 1101
0011 + 1101 = 1 0000  （进位溢出丢掉）→ 0000   加法终于对了
```

课件 Table 6-1（4 位）摘要：

| 十进制 | 符号位表示 | 1 的补码 | 2 的补码 |
|--------|------------|----------|----------|
| +3 | 0011 | 0011 | 0011 |
| 0 | 0000 | 0000 | 0000 |
| −1 | 1001 | 1110 | 1111 |
| −3 | 1011 | 1100 | 1101 |
| −7 | 1111 | 1000 | 1001 |

老师：实验里几乎不会手算补码，但 **Quiz / 概念题会出**。Tutorial Q3 就是。

##### 课件例题：把 −28 写成 8 位 2 的补码

**Step 1** 写 28 的 8 位二进制（反复 ÷2，再左边补 0）：

```
28 ÷ 2 = 14  余 0
14 ÷ 2 =  7  余 0
 7 ÷ 2 =  3  余 1
 3 ÷ 2 =  1  余 1
 1 ÷ 2 =  0  余 1
```

\(11100_2\)，补成 8 位：`00011100`

**Step 2** 取反（1 的补码）：`11100011`

**Step 3** +1（2 的补码）：`11100100`

所以 **−28 = `11100100`**（8 位 2 的补码）。

验算：最高位是 1 → 负数；对 `11100100` 再做一次「取反 +1」应回到 28：

`11100100` 取反 `00011011`，+1 → `00011100` = 28。正确。

##### Tutorial Q3：把 −56 写成 8 位 2 的补码

老师当堂留作回家题。做法与 −28 完全相同。

**Step 1** \(56 = 32+16+8 = 00111000_2\)

**Step 2** 取反：`11000111`

**Step 3** +1：`11001000`

**答案：`11001000`**

验算：`11001000` 取反 `00110111`，+1 → `00111000` = 56。

#### 1.1.4 十六进制（Hex）

4 个二进制位合成 1 个十六进制位。记忆：A=10, B=11, C=12, D=13, E=14, F=15。

老师：看 PLC 内存时几乎全是 hex。一屏二进制全是 0，什么都找不到；hex 把 4 bit 压成 1 个字符，扫一眼就能定位非零单元。

课件例子：\(2D6_{16}\)

| Hex 位 | 对应 4 bit |
|--------|------------|
| 2 | 0010 |
| D | 1101 |
| 6 | 0110 |

所以 \(2D6_{16} = 0010\,1101\,0110_2\)

**正确的十进制换算：**

\[
2D6_{16} = 2\times 16^2 + 13\times 16^1 + 6\times 16^0 = 2\times 256 + 208 + 6 = 726_{10}
\]

课件第 8 页把 \(16^2\) 那一项写成了 \(7\times 256=448\)，且 \(13\times 16\) 也算错，最后得到 610。**那是幻灯片笔误，考试按正确公式算。**

#### 1.1.5 BCD（Binary Coded Decimal）

每个十进制数字 0–9 单独用 4 bit 编码，**不用 A–F**。

课件：十进制 **5836**

```
5 → 0101
8 → 1000
3 → 0011
6 → 0110
```

你「看见」的 5836，就是十进制 5836。若把同一串 bit 当成 **hex** 的 `5836`，值就完全不是 5836。

老师类比：老式七段数码管、BCD 拨码开关。计算机内部计算仍用二进制；**给人看、从拨盘读入** 时用 BCD 更直接。会浪费一点编码空间（4 bit 能表示 0–15，BCD 只用 0–9）。

典型硬件：四位 BCD 拨码开关，每位 4 根线（权 1, 2, 4, 8）进 PLC 输入模块。例如数字 3 → 触点 1 和 2 闭合（`0011`）；数字 6 → 触点 2 和 4 闭合（`0110`）。

##### TOD / FRD 指令

| 指令 | 含义 | 典型用途 |
|------|------|----------|
| **TOD** (TO Decimal / Convert to BCD) | 整数 → BCD | 把 PLC 内部数送到七段显示器（Dest 常为输出字，如 `O:10`） |
| **FRD** (From Decimal / Convert from BCD) | BCD → 整数 | 把拨码开关读进来（Source 常为输入字，如 `I:2`） |

**Overflow 位 (V)**：

- TOD：BCD 结果超出 **0–9999** 时 V=1
- FRD：源不是合法 BCD（某一组 4 bit > 9），或值大于 **32767** 时 V=1

老师：现在很少用老式数码管，但 PLC 仍保留这些模块，**正反转换要会**。

### 1.2 算术指令与 MOV（Arithmetic and Move）

#### 1.2.1 Allen-Bradley：一种运算一个块

AB 为加、减、乘、除、开方……各做一块。每块三个口：

- **Source A**：第一个操作数（内存地址 **或** 常数）
- **Source B**：第二个操作数（内存地址 **或** 常数）
- **Dest**：结果必须写入内存地址（不能是「虚空」）

触发：左边触点为真时执行。

课件例 (a)：`40 + 15 = 55`

```
I:001/0 ───[ ADD ]
              Source A: N7:1      （当前值 40，是变量）
              Source B: 15        （常数，没有地址）
              Dest:     N7:3      （结果 55 写到这里）
```

课件例 (b)：用计数器累加值去设定定时器

```
I:001/1 ───[ ADD ]
              Source A: N7:4          （100）
              Source B: C5:1.ACC      （计数器 1 的累计值）
              Dest:     T4:3.PRE      （写入定时器 3 的预设值）
```

含义：`定时器预设 = 100 + 计数器当前值`。算术结果可以动态改 Timer/Counter 参数。

课件还有：`(c) 45−25=20` 用 SUB；`(d) 20×3` 用 MUL；`(e) 40/5` 用 DIV。结构完全一样。

老师：若要算 `3+4+5`，AB 必须 **两块 ADD** 串起来。很笨。

**Siemens（实验用）**：一块 `CALCULATE`。公式栏直接写 `X+Y+Z`，输入输出自己连地址。和 Simulink 框图很像。考试若要求画 AB 块，仍按 Source A/B/Dest 画。

##### 课件例题：华氏度 → 摄氏度

\[
C = 5(F-32)/9
\]

AB 必须拆成三步，每步一个中间地址。课件用 \(F=212\)（水沸点）演示，应得 \(C=100\)。

| 梯级 | 指令 | Source A | Source B | Dest | 本例数值 |
|------|------|----------|----------|------|----------|
| 0000 | SUB | `N7:1` (F=212) | `N7:2` (32) | `N7:3` | 180 |
| 0001 | MUL | `N7:3` (180) | `N7:4` (5) | `N7:5` | 900 |
| 0002 | DIV | `N7:5` (900) | `N7:6` (9) | `N7:7` | **100** |

三行都由同一个触点 `I:1/1`（Calculate）使能。PLC **从上到下扫描**，同一扫描周期内 SUB 的结果立刻可供 MUL 使用。

Siemens 实验里一行公式就能写完。

#### 1.2.2 MOV：把「正在跳的输入」拍成一张静止的快照

模拟量端子上的数 **每个扫描周期都在变**。MOV 的意思是：把 Source **复制** 到 Dest，Dest 里的值从此不再跟着传感器抖（除非你再 MOV 一次）。

三种 MOV 类指令（课件）：

| 指令 | 作用 |
|------|------|
| **MOV** | 整字复制 |
| **MVM** | 带掩码，只复制指定位 |
| **NEG** | 复制其相反数（2 的补码取负） |

老师：实验测温度、颜色、距离，**一律先 MOV 到自己的内存变量**，不要直接拿输入字去做比较和计算。

#### 1.2.3 数学/MOV 块的四种触发方式（Figure 6-12）——非常重要

PLC 程序 **永不停止**，扫描一遍立刻再来。所以「这块加一次」和「这块每秒加几百次」是两件完全不同的事。

| 标准 | 左边条件 | 行为 | 适用 |
|------|----------|------|------|
| **A** | 无触点（梯级永远为真） | **每个扫描**都执行 | 连续跟踪实时数据，例如每扫一次就更新一次颜色寄存器 |
| **B** | 普通触点 | 条件为真的 **每一个扫描** 都执行 | 传统「条件满足就算」 |
| **C** | 触点 + **OSR**（One Shot Rising） | 只在 FALSE→TRUE **那一个扫描**执行一次 | 传感器来一个脉冲，只采样一次 |
| **D** | 触点 + OSR，且 Dest 与某个 Source 是同一地址 | 累加/累减一次（类似 `x = x + k`） | **必须**限制执行次数，否则一个扫描加一次，立刻溢出 |

**OSR**：把任意长短的输入，变成 **一个扫描宽的脉冲**。老师：累加（`N7:0 = N7:0 + 1`）时如果不用 OSR，这个数会以扫描频率狂加。

也可用 Timer+Counter 做单次触发，但 OSR 是推荐写法。

##### 课件大题：颜色传感器采两次再平均（Figure 6-14 / 6-15）

**题意**

- 颜色模拟量来自 `I:2.0`
- 触发脉冲接在槽 4 端子 0 → `I:4/0`
- 颜色有效窗口 **500 ms**
- 触发比有效窗口 **晚 5 ms** 变真，并保持 **700 ms**

时序推论（这是本题的陷阱）：

```
有效数据 |████████████|  500 ms
触发     ..|████████████████|  700 ms，晚 5 ms 开始
重叠好数据     约 495 ms
触发后半段仍为真、但颜色已掉沿  → 坏数据
```

若在触发为真的 **整段时间** 里一直 MOV，后半段会采到肩部/掉沿，颜色会判错。老师实验里也强调：颜色是 **一个范围**，边缘会重叠，只采肩部会读错。

**解法思想**：在好数据窗口里采 **两次**，求平均。第一次在触发上升沿（OSR，一定落在好窗口里）；等 400 ms 再采第二次（仍 < 495 ms）。

课件梯形图：

```
0000  I:4/0 ── OSR B3/0 ── MOV   Source I:2.0 → Dest N7:0     第一次采样

0001  I:4/0 ──]/[ T4:0/DN ── TON T4:0
                               Time base 0.01 s
                               Preset 40          → 40×0.01 = 0.40 s

0002  T4:0/DN ── MOV   Source I:2.0 → Dest N7:1               第二次采样

0003  T4:0/DN ── ADD   N7:0 + N7:1 → N7:5

0004  T4:0/DN ── DIV   N7:5 / 2    → N7:2                     平均值
```

为什么 TON 前面要串 `T4:0/DN` 的常闭？定时器 Done 之后立刻让使能变假，避免它在触发仍为真时被反复复位/重跑。OSR 保证第一次 MOV 只发生一次。

老师补充（实验）：两次读数差太大就丢掉重采，直到两次接近（例如 1% 以内）才认为可靠。温度通常很稳；**分拣实验的颜色传感器必须这样处理**。

### 1.3 比较指令（Comparison）

AB 又是「一种关系一块」：

| 指令 | 含义 |
|------|------|
| EQU | 等于 |
| NEQ | 不等于 |
| LES | 小于 |
| GRT | 大于 |
| LEQ | 小于等于 |
| GEQ | 大于等于 |
| MEQ | 掩码后相等 |
| **LIM** | 是否落在某区间内/外（直接测范围） |

Siemens：一块 Compare，自己填 `<` `>` `<=` 等。

比较指令是 **输入类**（放在梯级左边当条件），为真则右边输出执行。温度滞环、颜色分档、电梯到位，全部靠它。

老师硬性建议：比较时 **先把 PLC 原始读数换算成真实物理量**（°C、mm、颜色工程单位），再和 20°C、30°C 比。不要和内存里的 `3456` 这种无量纲数比——调试时你自己都看不懂。

### 1.4 程序控制（Program Control）

课件三个：MCR、JMP/LBL、子程序。老师态度非常鲜明。

#### Master Control Relay (MCR)

两道 MCR 围成一个「围栏」。围栏使能为真 → 内部梯级正常；使能为假 → 围栏内 **非保持型** 输出被强制为假（线圈掉电）；**保持型**（如锁存的电磁阀）保持原状。

课件例子：总开关 `I:1/1`

- 开：加热器、指示灯、电磁阀按各自条件工作
- 关：加热器和灯灭（非保持）；电磁阀若是保持型指令，**继续开**

老师：**不要用。** 你完全可以把条件写在每一行左边，效果相同，而且翻到程序中间时你仍知道自己在哪个 if 里面。MCR 围栏一长，读到一半会迷路。考试不考你「必须用 MCR」。

#### Jump / Label（JMP / LBL）

条件成立就跳到某条带 LBL 的梯级，中间不扫描。能缩短扫描时间。老式语言的 `GOTO`。

课件警告：

- 跳过的 Timer/Counter **不会累加**（因为那一行没被扫到）
- **禁止向后跳**（容易死循环）
- LBL 必须是该梯级 **第一个** 输入指令
- **永远不要跳进 MCR 区**（谁在控制这些梯级会说不清）

老师：**现代语言基本禁用。过时，不要用，考试程序里也不要写。**

#### 子程序（JSR / SBR / RET）——唯一真正有用的

| 指令 | 角色 |
|------|------|
| JSR | 主程序里「调用子程序」（输出指令） |
| SBR | 子程序文件的第一梯级（输入指令，标记入口） |
| RET | 返回主程序 |

两种该用的场合：

1. 同一段逻辑要跑 **很多次**（开机序列十几行，多处都要调）
2. 这段本身很长（例如 20 行），抽出去主程序才读得懂

经验：重复超过约 3 次就考虑封装。老师：本课实验程序通常 < 100 行，**不一定用得上**；若调用需要「只跑一次」，前面加 OSR。

## 2. Analog sensor（模拟量传感器）——实验核心

到目前为止，课上的 I/O 几乎全是 **离散量**：开/关、真/假。实验要测温度、距离、颜色，读数是一个 **连续数值**。

### 2.1 信号链：你真正该关心哪一段

```
物理量（°C、mm、颜色）
    → 传感器内部（电阻 / 热电势 / …）
        → 调理电路（供电、放大）→ 电压或 4–20 mA
            → PLC 模拟量端子 → A/D → 内存里的整数（如 3456）
```

老师画了这条链之后说：**中间那些电压、电阻，做实验的人通常不用管。**

实验室你会同时有：

- 万用表/温度计给出的 **真值**（例如 20°C）
- PLC 监视画面里的 **原始整数**

任务是做 **标定**：多测几个点，在 Excel 里拟合「PLC 读数 ↔ 物理量」。以后程序里用这条映射。

**标定步骤（温度为例）**

1. 传感器放入 20°C 水，记 PLC 读数（如 1234）
2. 升温 5°C，再记
3. 再升 5°C……
4. 假设近似线性，拟合直线；非线性就做插值表，**不要外推**

老师强调的两个会「读数扭曲」的坑：

1. 外部供电不够硬，传感器被拖垮
2. PLC 模拟端子常见能力大约 **4–20 mA**；超出量程会饱和、失真

### 2.2 温度传感器三种

| 类型 | 原理 | 要不要供电 | 本课实验 |
|------|------|------------|----------|
| **RTD**（Resistance Temperature Detector） | 金属电阻随温度变 | 要（电桥） | **实验用这个** |
| Thermistor | 电阻随温度大变，有 NTC / PTC | 要 | 了解即可 |
| **Thermocouple** 热电偶 | 两种不同金属接点产生 mV 级电压（Seebeck） | **不要**，但信号太小通常要放大 | 实验不用；Type K 很常见，约 −200°C 到 1370°C，室温附近很线性 |

RTD：常见是 **PTC**（温度↑电阻↑）。老师不提前告诉实验里那只是正还是负，让你自己测两点看斜率。

**PTC**：电阻-温度曲线向上；**NTC**（多数热敏电阻）：向下。

热电偶：一根电缆，一端焊在被测金属上，另一端出现小电压。Type K 是实验室常见型号。

##### 课堂随堂题（字幕里老师现场算，公式来自传感器数据手册）

线性 RTD：

\[
R_T = R_0 \bigl(1 + \alpha (T - T_0)\bigr)
\]

典型 Pt100：\(R_0=100\,\Omega\)（0°C），\(\alpha \approx 0.00385\,/^\circ\mathrm{C}\)，\(T_0=0\)。

**(a)** \(T=40°C\) 时的电阻

\[
R_{40} = 100\bigl(1 + 0.00385\times 40\bigr) = 115.40\,\Omega
\]

**(b)** 测得 \(R=119.25\,\Omega\)，求 \(T\)

\[
119.25 = 100\bigl(1 + 0.00385\,T\bigr) \Rightarrow T = \frac{0.1925}{0.00385} = 50°C
\]

**(c)** 0–100°C 对应 4–20 mA，求 50°C 的电流（线性假设）

中点：\(4 + (20-4)/2 = 12\,\mathrm{mA}\)

老师：换一种传感器、换华氏单位，公式系数全变。**正确做法是查该型号数据手册**，不要把这条公式当宇宙定律。

### 2.3 模拟量输入特性

选模拟量模块要看三件事：

1. **Unipolar 单极性**（只正）：常见 0–5 V、0–10 V。传感器一端接公共地，占 **一个** 输入端子。
2. **Bipolar 双极性**（正负）：常见 ±5 V、±10 V。占 **两个** 端子（+ 和 −）。
3. **分辨率（bit 数）**：常见 10 / 12 / 14 bit。bit 越多越贵。

老师：实验里通常用单极性 0–5 V 对应某段物理量。

#### 分辨率公式（单极性）

\[
\text{电压分辨率} = \frac{V_{FS}}{2^n}
\]

\(n\) 是 bit 数，\(V_{FS}\) 是满量程。

课件 4 bit、0–10 V 的极端例子（现实中不会买 4 bit，只为算得清）：

- 档位数 \(2^4=16\)（含 0）
- 每档 \(10/16=0.625\,\mathrm{V}\)
- 最大码 `1111` = 15，对应 \(15\times 0.625=9.375\,\mathrm{V}\)，**到不了 10 V**

输入变化小于 0.625 V，PLC 无感。

10 bit、0–10 V：\(2^{10}=1024\) 档，分辨率 \(\approx 10/1024 \approx 0.0098\,\mathrm{V}\)。

**经验法则（课件原文，Tutorial Q1 会用）：** 选模块时，电压分辨率应 \(\le\) 你所需测量分辨率的 **25%**，也就是档位数至少是「量程/所需精度」的 **4 倍**。

#### 双极性分辨率（offset binary）

量程按 **全跨度** 算。例：4 bit，−10 V 到 +10 V：

- 全跨度 20 V，分辨率 \(20/2^4=1.25\,\mathrm{V}\)
- `0000` → −10 V
- `1111` → \(+10 - 1.25 = +8.75\,\mathrm{V}\)
- 半量程 `1000` = 8 → \(-10 + 8\times 1.25 = 0\,\mathrm{V}\)

### 2.4 模拟量输出与负载阻抗（会「饱和」的那道题）

D/A 后面是运放，**最大电流有限**（课件典型约 25 mA，例题用 20 mA）。负载太小（电阻太小）时，还没到满电压，电流已经顶死，电压上不去。

要满幅不饱和：

\[
R_{load} \ge \frac{V_{max}}{I_{max}}
\]

##### 课件例题（AO Example）

> 12-bit、10 V bipolar 模拟量输出，\(I_{max}=20\,\mathrm{mA}\)。  
> (1) 负载 1 kΩ，系统正常吗？  
> (2) 负载 330 Ω 呢？

\(R_{min}=10\,\mathrm{V}/20\,\mathrm{mA}=0.5\,\mathrm{k}\Omega=500\,\Omega\)

**(1) 1 kΩ > 500 Ω**  
满压电流 \(I=10/1000=10\,\mathrm{mA}<20\,\mathrm{mA}\)。**正常。**

**(2) 330 Ω < 500 Ω**  
若硬要 10 V，需要 \(I=10/330\approx 30.3\,\mathrm{mA}>20\,\mathrm{mA}\)。实际电流被卡在 20 mA，饱和电压：

\[
V_{sat}=20\,\mathrm{mA}\times 330\,\Omega=6.6\,\mathrm{V}
\]

输出只能到约 6.6 V，到不了 ±10 V。**不正常。**

读传感器时同理：供电不够或负载电阻过小，读数会被压扁。

### 2.5 模拟量在 PLC 内部怎么存

离散量占 1 bit；模拟量占多个 bit。通常：

- 12 bit 的 A/D 仍占用 **一个 word（16 bit）**，浪费几位，但存储对齐更简单
- 把 A/D 做成 16 bit 会明显更贵，所以模块常见 10–14 bit

##### 课件例题（Analog Data Handling）

> 3.500 V 加到 **8-bit、5 V 单极性** 模拟量输入。监视软件显示寄存器为 \(263_8\)（八进制）。模块工作正常吗？

**Step 1** 八进制 → 十进制

\[
263_8 = 2\times 8^2 + 6\times 8 + 3 = 128+48+3 = 179_{10}
\]

**Step 2** 8 bit 共 \(2^8=256\) 档（按课件公式 \(V_{FS}/2^n\)）

**Step 3** 比两个比例是否一致

\[
\frac{179}{256} \approx 0.699 \qquad \frac{3.5}{5}=0.700
\]

几乎相等（量化误差 1 档之内）。**工作正常。**

老师：实验里你往往 **不知道端子上真实电压**，只知道 PLC 整数和万用表测的物理量。标定仍然是「物理量 ↔ 寄存器」，不一定经过电压这一步。

## 3. Closed-loop control（闭环控制）

第一讲就说：PLC 最终是为了 **控制过程**。控制课（MACH365 / ACT344）默认执行器能给出连续、任意的力/速度。现实常常不是。

本课实验三种执行器：

| 对象 | 执行器 | 你能控制什么 |
|------|--------|----------------|
| 水箱 | 加热器、泵 | **只能开/关**（数字量） |
| 分拣机器人 | 吸盘、去向位 | **只能开/关** |
| 电梯 | 直流电机 | **电压连续可调**（模拟量输出）→ 唯一能做真正连续控制的一套 |

分类：

**间歇 / 离散（Intermittent）**

- On-off（单点开关）
- Two-position（带滞环，老师说「以后说 on-off 就是指这个」）
- Floating / multi-position（0% / 50% / 100%）

**连续（Continuous）**——需要模拟量执行器

- P, PI, PD, PID, Fuzzy  
- 都是 **无模型** 的：不用传递函数，靠试参数。老师：真正建模型极费时（后面 Simulink 实验会体会）。工业更常用这类；前沿还有 data-driven / 神经网络。PID 细节当堂跳过，说「挺直接」。

### 3.1 单点 On-off 为什么不行

设定 40°C：高于 40 关加热，低于 40 开加热。想法对，结果是执行器在 40°C **附近疯狂抖**，设备很快坏。课件：单点 on-off 不常用，因为误差过零时控制元件切换太频繁。

### 3.2 Two-position = On-off + 滞环（Hysteresis）——实验默认策略

两个不同阈值，中间 **死区 / 中性区** 什么都不做。

暖气例子（课件）：

- 设定点 70°F
- 降到 **68°F 开** 炉子
- 升到 **72°F 关** 炉子
- 周期：温度在两限之间锯齿振荡；阀门矩形波通断

代价：牺牲精度（这里 ±2°F）。收获：执行器切换次数大降，系统稳定。

**带宽越大**：泵/加热器通断越少，振荡幅度越大。  
**带宽越窄**：更准，但切换更勤。这是 **稳定 vs 精度** 的权衡。

实现：两个比较指令 + 自锁（seal-in），不要只用一个 LES。

```
      LES (T < T_low)                 Heater
-----] [---------+-------------------(  )----
                 |
      Heater     |     GRT (T > T_high) 常闭
-----] [---------+-----]/[-------------------
```

低于下限 → 强制接通并自锁；高于上限 → 常闭断开，加热器关；中间保持上一状态。

##### 课件例题：实验室温箱 ±0.5% 滞环

> 温箱允许环境温度到 500°F。设定点由拨盘给定，本例 **300°F**。  
> 上下限为设定点的 **±0.5%**。  
> - 低于下限：加热器开，灯开  
> - 高于上限：加热器关，灯开

\[
0.5\% \times 300 = 1.5°F
\]

- 下限 \(T_L=300-1.5=\mathbf{298.5°F}\)
- 上限 \(T_U=300+1.5=\mathbf{301.5°F}\)

程序结构：

1. FRD：拨盘 BCD → 整数设定点（本例 300）
2. 算术：`band = 0.005 * SP`，`T_L = SP - band`，`T_U = SP + band`  
   （若只用整数文件，可先把温度放大 10 倍变成 2985 / 3015，或用浮点文件）
3. 比较 + 自锁控制加热器
4. `LES T<T_L` 或 `GRT T>T_U` 点亮超限灯（可同一只报警灯）

老师：比较请对 **已经换算成 °F 的变量** 进行，不要对原始 A/D 码。

### 3.3 Floating / 多档控制

例如冷却：0%、50%、100% 三档。切换频率比纯两位置更低，介于离散与连续之间。了解即可。

### 3.4 连续控制（P / PI / PD / PID）

仅当执行器能给连续输出（电梯电机电压、变频泵转速）时才有意义。

误差：\(e(t)=SP-PV\)

| 形式 | 公式要点 | 解决什么 |
|------|----------|----------|
| **P** | \(u=K_p e\) | 把 PV 拉向设定点；有稳态误差 |
| **PI** | P + \(\int e\) | 消稳态误差；积分从不单独用 |
| **PD** | P + \(de/dt\) | 抑制快速扰动，减超调 |
| **PID** | 三项都有 | 最常用组合 |

P 的增益定义（课件）：

\[
K_p = \frac{\text{输出变化百分比}}{\text{输入变化百分比}}
\]

需要 P 而不是 on-off 的场合：必须钉在某一设定点、过程热容很小、存在扰动。

老师：水箱实验 **没有** 可变功率加热器 / 变频泵，所以实验用滞环；电梯 **可以** 按距离远近调电压（近了减速），但不是强制。PID 整定放到后面 Simulink / Simscape 实验。

##### Tutorial Q4（老师：这是实验水箱的一半，要讲透）

> 进水 60°C，水箱要维持 **40°C**。多余水从顶部溢流（液位不用管）。温度传感器测箱内温度。讨论控制策略和精度。  
> 1. 泵只能用 DO 开/关  
> 2. 泵由 AO 调速

房间比 40°C 冷。不泵热水，箱子会慢慢凉；泵入 60°C 水（同时溢流），平均温度上升。

**策略 1 — 数字量泵（实验真实情况）**

不能钉死 40°C，必须留滞环。老师示范 ±2°C：

- \(T<38°C\) → 泵开（灌 60°C 水）
- \(T>42°C\) → 泵关
- 38–42°C 不动作

温度轨迹：到 38 开始爬升 → 到 42 开始下降 → 锯齿波。泵输出是矩形波。

带宽改成 35–45°C：振荡更大，泵切换更少。  
带宽改窄：更准，泵更勤。

精度：由你选的带宽决定，例如 ±2°C。这是硬件（只有 DO）下的上限，不是 PID 没调好。

**策略 2 — 模拟量调速泵**

可做 PI/PID：

- 远离 40°C 时泵得快
- 接近时减速，可能有一点超调
- 稳态：泵持续以很小流量送 60°C 水，正好抵消散热，温度贴在 40°C

精度远好于策略 1，但要求执行器能连续调，还要整定 PID。老师：实验室水箱走策略 1；电梯才有条件走策略 2。

实验完整版还有 **两个水箱**：下箱有加热器（冲 60°C 一类设定），上箱靠泵热水和侧孔回流维持较低温度。泵一开，上箱升温、下箱降温，加热器和泵的逻辑会耦合。Q4 是其中「单箱 + 泵」这一半。

8. 寄存器比例 \(\approx V/V_{FS}\)（注意进制：\(263_8=179\)）

10. Q4：DO 泵 = 滞环锯齿；AO 泵 = PID 可稳态。带宽 = 精度 vs 切换次数
11. 不要 JMP，不要 MCR；子程序可选
12. Siemens：`I` / `Q` / `MW`，`IW64` 先 MOV；CALCULATE 一块顶一串 ADD
